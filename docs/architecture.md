# Architecture

The firmware runs on an ESP-12F (ESP8266, 80 KB of RAM shared by static data and
the heap, 1 MB window for code, 4 MB flash with 1 MB LittleFS) driving a 1.54"
240×240 ST7789 panel over SPI. Everything below follows from those limits: no
frame buffer, small JSON documents, strings in flash.

## Start-up and the main loop

`src/main.cpp`:

1. Read the settings (`Settings.cpp`, LittleFS `/config.json`), set the system
   language (`SysText`), start the display with a splash and a progress bar.
2. Join the strongest saved Wi‑Fi network (`Net.cpp`), or open the setup
   hotspot with a QR code when none can be joined.
3. Start the clock (SNTP, only when something needs the time), the web server
   (`WebPortal.cpp`) and every app.
4. `loop()`: serve HTTP, keep the network healthy, pick and draw the screen.

What is drawn, in priority order: a notification banner, the running timer,
the Nightstand at night, then the selected app or the rotation.

## Apps

Each app is a `DisplayMode` (`src/Mode.h`) with `service()` to fetch and draw,
`invalidate()` when the settings change and `wake()` when it comes back on the
screen. The registry in `main.cpp` lists them; the rotation steps through the
ticked ones and fades the backlight between them.

| App | Folder | Draws with |
| --- | --- | --- |
| Watch face | `src/features/theme/` | `ThemeEngine` (layers, bindings) and `ThemePackage` (`.stheme`) |
| Calendar | `src/features/calendar/` | `CalendarView` |
| Reminders | `src/features/reminders/` | `RemindersView`, list in `/reminders.json` |
| Weather | `src/features/weather/` | `WeatherView`, data from Open-Meteo |
| Timer | `src/features/timer/` | `TimerView`, also an overlay and a banner |
| Nightstand | `src/features/nightstand/` | `NightstandView`, an overlay |
| Notifications | `src/features/notify/` | `NotifyView`, an overlay with a queue |

The `*View` files are plain C++ without Arduino: `layout()` computes what goes
where, `renderRow(y)` fills one 240-pixel row. The mode draws row by row into a
480-byte buffer, so a screen never needs 115 KB of RAM, and the same code runs
in the desktop tests that write PPM images. Shared drawing helpers are in
`src/features/AppDraw.h`; the device's own screens (splash, setup, crash) are
`src/ScreenView.cpp`.

## Text and language

One font family in six styles (`src/features/theme/SystemFont*`, generated by
`tools/gen_system_font.py`) covers ASCII, Cyrillic and `°`. Text is stored as
UTF-8 and turned into one-byte "display bytes" (`displayTextTo`) before drawing.

The device language is `clock.lang`: `en` (default) or `ru`. It names the words
on every screen (`SysText.cpp` for the system screens, a `PROGMEM` table in each
view for the apps) and the language of the web page. Word tables live in flash:
on the ESP8266 a string literal in code is RAM.

## Web page

`src/webui.html` is the whole page (HTML, CSS, JS). `tools/gzip_webui.py`
minifies and gzips it into `src/webui.h`, served from flash. The page reads
`/api/config` and `/api/status` and saves changes as they happen (no Save
button), except for the Wi‑Fi list, the name, the hotspot and the password,
which restart the device or lock the page and have their own buttons.

Translation: the page is written in English. `lz(text)` looks a message up in
the `RU` table, `lzPage()` swaps the static text once. Rules that keep it safe:
code never reads a translated text back (state is in values and `data-*`),
values sent to the device are never translated, and user data (network names,
reminders, face names) is marked `translate="no"`. Every `lz('…')` key must be
in `RU`; `tests/i18n` checks it.

The page is also a home-screen web app: `/manifest.webmanifest` and the icons
from `src/PwaAssets.h` (`tools/pwa_icon.py`, `tools/gen_pwa.py`).

## Network

- Up to 4 saved networks; at start the strongest one in range is joined.
- Modem sleep is off: with it, some routers dropped the device silently.
- A watchdog pings the gateway; after 4 missed answers it rejoins, after 10 it
  restarts. The reason of such a restart survives in RTC memory and shows in
  `/api/status` (`net`).
- The web server answers one request at a time; `WebGuard.h` refuses requests
  from other origins and host names (CSRF and DNS rebinding).

## Memory

Free heap is about 25 KB at rest and about 20 KB at worst (the whole page
loading at once). Rules that keep it there:

- No frame buffer; draw a row at a time.
- Tables and strings in `PROGMEM`; `std::to_string` and literals cost RAM.
- `ArduinoJson` documents with filters; stream large replies
  (`JsonStream.h`, `StatusJson.h`) instead of building them.
- The watch face is released before a request that needs memory
  (`appRelease()`), and loaded again afterwards.
- `tools/gfx_tables_to_flash.py` moves the GFX library's unused JPEG tables
  (6.8 KB) out of RAM at build time.

To see what holds RAM:
`xtensa-lx106-elf-nm -S --size-sort -C .pio/build/geekmagic/firmware.elf | grep -iE " [bBdDrR] "`.

## Settings

`Settings.h` has one struct per slice (`clock`, `display`, `auth`, `button`)
plus the shared fields. `settingsApplyJson()` applies only the keys present, so
a save can be partial; `settingsToJson()` leaves passwords out of the web API.
Keys of removed features in an old file are ignored and dropped by the next
save. Writes are atomic (`AtomicJson.h`).

## Known issues

- A software watchdog reset was once recorded inside the Wi‑Fi driver
  (`pm_send_nullfunc`), after 13 minutes of uptime. It has not repeated; the
  crash record shows in **General → About** until cleared.
